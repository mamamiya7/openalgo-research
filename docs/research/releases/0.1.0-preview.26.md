# OpenAlgo Research 0.1.0-preview.26

New editable automatic research uses the CSV or Chartink history supplied by the
trader. It no longer requires a longer signal export to complete the current
bounded research programme.

## Changes

- Record the explicit v16 `history_policy: available_history` on new editable
  submissions and early preparation. Old frozen jobs and exact replay retain
  their original settings and recipes.
- Retain chronological checks when the supplied dates support them. Comparisons
  on this reusable dataset are labelled historical, without an independent-data
  claim.
- When separate complete later periods are unavailable, allocate the existing
  six fits to expanding historical prefixes and full-history seed repeats. The
  programme retains all 408 proposals and the 512-account ceiling, the unchanged
  baseline and search ranges, causal features, complete holding boundaries,
  coverage admission, transaction costs and hard risk constraints.
- Preserve the primary full-history seed-0 selection. Historical prefixes and
  repeated seeds are diagnostics; later or better-looking seeds cannot replace
  it. No final account, independent validation or supported recommendation is
  invented for a short history.
- Record available-history scope in the frozen recipe, mandate and findings;
  preserve it when saving, reopening or inspecting a child report. Existing
  strict saved findings keep their original interpretation.
- Record checkpoint coverage for the two registered v15/v16 seed-repeat fits.
  The observer previously admitted only the first four fits, interrupting a
  complete six-fit programme. Global proposal ordinals, per-fit limits and
  exact checkpoint/outcome matching remain mandatory.
- Prepare exact historical reports on the recorded full-history search period
  without assuming that an independent final period exists. Requests for a
  nonexistent later period remain refused.

## Qualification

257 focused backend tests and 210 frontend tests pass. These cover the full
408-proposal path, exact completed and partial resume, cancellation, resealed
evidence tampering, small calendars, unchanged old recipes, editable drafts and
saved-report history qualification, registered seed-repeat checkpoint coverage
and rejection of unregistered fits. Child and frozen saved reports read the
recorded scope from their immutable parent study through the existing job API.
TypeScript, the production frontend build,
focused style checks and archive integrity checks pass. Static resource review
found no new connections, files, threads or persistent caches in the planner or
runner branch; the existing prepared owners still close on all exit paths.

The installed Windows acceptance completed the supplied 1,869-signal,
146-stock, 160-session scanner. All 408 proposals completed across six fits;
the result retains 325 recorded account simulations within the unchanged
512-account ceiling. Historical prefixes contain 103, 122, 141 and 160 sessions.
The requested baseline still holds for 45 sessions, and the search still extends
to 82 sessions with the original risk constraints. The result records
`exploratory_only`, no independent final account, no invented later-period
checks, and no independently validated recommendation.

The exact selected report reproduced its recorded account evidence. It was
saved as a named setup, the application reloaded, and its pinned report reopened
with the 160-session historical qualification visible. No orders or trading-mode
changes were made.

The full automatic one-minute target is **not met**. This qualification took
1,220.113 seconds of wall time from job creation to completion, including an
interruption, correction and checkpoint resume. Linux compatibility checks also
overlapped the early part of the attempt, so this is not a clean performance
benchmark. The separate exact selected report took 33.568 seconds. The earlier
preview.25 result below one minute qualifies the cached fixed backtest only;
it does not qualify this full automatic programme.

The programme does not guarantee that a historical winner will perform in future.
Malformed inputs, missing prices and failed integrity/risk checks remain errors;
limited signal history alone is no longer a reason to demand another export.

The Linux gthread compatibility run passed 1,449 checks with three skips, but
retains eight failures and three fixture errors in existing host-contract tests:
the fork's container research launcher differs from upstream eventlet/gthread
launcher expectations, its shell attributes differ, and seven pre-existing
check-then-act sites lack review annotations. These paths were not changed or
waived in this batch. This release does not claim complete Linux host-suite
qualification.
