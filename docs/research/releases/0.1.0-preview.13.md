# OpenAlgo Research 0.1.0-preview.13

Cached preparation performance correction on the same OpenAlgo 2.0.2.7,
dependency locks and financial versions as preview.12. Installation is unchanged.

## Changes

After the final cache-read group completely covers the required prices, publish
one final verification checkpoint instead of three intermediate checkpoints.
Partial groups, missing prices, broker responses, cancellations and time-budget
yields keep their durable saves. Broker observations still publish before mutable
ingestion and exact readback. No quota cache or relaxed admission was introduced:
every new artifact retains the strict storage/entry/symlink checks.

This fixes measured repeated work in the normal installation's large research
store. Its strict scan was efficient individually, but nested checkpoint saves
repeated it several times for every cached stock. The earlier isolated-store
stock timing does not describe that normal-store overhead.

Per-bar engine progress retains its live cancellation/ownership read, without
also performing a forced pause-boundary write on every bar. Pause acknowledgement
stays before calculation and after durable completed-calculation checkpoints.
A concurrent progress read/save now says “Updating saved progress…” rather than
showing a verification warning; corrupt evidence still fails closed.

## Qualification

- 94 focused acquisition, cancellation/recovery, stock-context, pause, live-progress
  and strict artifact-publication checks passed; two platform-specific checks
  skipped. Repeated prepared-owner and live-read resource checks are included.
- A controlled 29-stock cache fixture reduced callbacks from 87 to 29, preserving
  complete outputs and all receipt bytes. With strict scans of the actual normal
  store in its checkpoint callback, time fell from 23.790 to 9.752 seconds.
  The fixture uses synthetic OHLC and measures persistence overhead only; it is
  not real-data optimisation, fresh-broker or complete-journey timing.
- Six matched native accounts from the actual saved sample retained identical
  complete reports. Median account time was 3.839 seconds with per-bar duplicate
  writes versus 1.094 seconds with live reads alone; all 129 live fence reads
  remained. The control database was isolated. This excludes common progress
  heartbeats, checkpoint publication and other search work.
- Search budgets, seeds, validation rules, financial assumptions and evidence
  versions are unchanged. The full Windows/Linux matrix was not repeated.
- The public package reuses unchanged frontend assets only after matching their
  source and asset hashes. No dependency, host-call or installation changes.

The complete Chrome sample journey, active/elapsed timing, saved-history checks
and remaining performance limit are recorded in
[verification](../VERIFICATION.md#small-real-csv-chrome-acceptance--22-october-2026).
That test included two pauses for fixes; it is not a clean latest-build benchmark
or full-CSV timing claim.

## Install and update

Download the complete
[preview.13 ZIP](https://github.com/mamamiya7/openalgo-research/releases/download/research-v0.1.0-preview.13/openalgo-research-0.1.0-preview.13.zip)
and verify it against `SHA256SUMS`. Extract all files and run **Setup.cmd** on
Windows or **setup-research.sh** on Linux. VectorBT and Optuna are included;
Nautilus remains optional. Do not download Setup.cmd alone.

Existing users must stop the app and worker, back up their application and data,
preserve existing data paths, update application files and restart. See
[update instructions](../RUNTIME.md#preserve-data-during-updates). No new migrations.
The preceding history-overlap and optimisation corrections are included.
