# OpenAlgo Research 0.1.0-preview.21

This patch removes repeated runtime bookkeeping. Features, financial semantics,
validation, dependency pins and the 408-proposal/512-account maximum are retained.
OpenAlgo remains 2.0.2.9 and charts 2.6.7.

## Changes

- Durably reserve every native calculation before it starts; retain consumed
  attempt charges after interruption and enforce the existing total/lost limits.
- Publish up to 16 completed proposals and their fully validated immutable
  histories together. Pause, selection and account-check boundaries flush.
  A hard interruption may replay an unpublished group; those attempts remain
  consumed. Normal pause saves pending completed evidence before acknowledgement.
- Keep one owner-thread metadata connection with fresh, separately committed
  sessions. Every engine tick still reads current cancellation and ownership.
  Independent threads and unsupported factories retain separate connections.
- Reuse a private detached execution receipt after complete validation. Calendar,
  opportunity, scheduled entry and fill checks remain fresh for each account.
- Retain every scientific trial ledger and reconciliation while omitting display
  analysis that trial retention discards. Selected/final reports keep full analysis.
- Compact eligible checkpoints under the same logical hash, retaining chunk
  structure, leaf, path and size admission. Oversized/legacy formats remain supported.
- Batch fresh Windows directory metadata; strict portable fallback handles other
  platforms/filesystems. Symlinks, access errors, malformed records, quota and
  entry limits remain enforced. There is no inventory cache.
- Bound and detach canonical JSON before C encoding, preserving exact bytes and
  existing streaming fallbacks, cycle/non-finite/type/depth/node/byte guards.
