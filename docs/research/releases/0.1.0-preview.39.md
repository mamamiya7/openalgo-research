# OpenAlgo Research 0.1.0-preview.39

20 November 2026. OpenAlgo **2.0.3.4**, charts **2.7.3**, and the tested
automatic-research decision loop in one installable distribution.

[Download the installable ZIP](https://github.com/mamamiya7/openalgo-research/releases/download/research-v0.1.0-preview.39/openalgo-research-0.1.0-preview.39.zip).

## What changes

- Hands-off, guided and hands-on research share the same native study flow.
  Review the proposed settings, preserve existing scan signals, and inspect
  decisions and exact saved evidence.
- Each new automatic experiment identifies an actual failed check, a supported
  cause, a measurable prediction and what would disprove it. Native outcomes
  return to the next decision, including the distinction between repairing
  funding feasibility and passing performance validation.
- Complete checked configurations and remaining options inform stop reviews.
  Saved reasons distinguish model judgment, incomplete review and exhausted
  budgets.
- Repeated economic observations are warnings, not acceptance proof. The worker
  can reject a repeated mandatory higher-cost failure after three charged
  accounts when owned, sealed evidence establishes that failure. The remaining
  eleven checks are explicitly unrun. Different settings or incomplete proof
  retain the complete validation programme; acceptance is never inferred.
- The optional OpenAlgo Rust adapter is available for its declared supported
  configurations alongside VectorBT and the existing optional Nautilus runtime.
- The latest official host release brings chart corrections, scheduler
  resilience, endpoint-group latency reporting, Nuvama implementation and
  dependency updates. Existing private broker configuration is preserved.

## Qualification

The host update passed 261 focused backend checks, 196 frontend checks,
TypeScript/production build, frozen dependency compatibility and exact reopening
of the existing five-stock saved qualification with calculations/provider calls
forbidden. One platform-specific backend case is skipped. An unrelated broad
position-read module has an existing missing `sahi` specification and is not
counted as passing. See [host qualification](../UPSTREAM_UPDATE_20261120.md).

The decision-loop qualification used five real saved stocks and 68 signals.
ChatGPT supplied three explicit hypotheses, requested funding recovery after a
blocked test, and proposed a different exit configuration after feedback. The
repeated-failure case cost three accounts; the funding and different-configuration
controls cost fifteen and fourteen accounts, retaining full native validation.
Results saved and reopened exactly. No tested setup passed performance
validation. Qualification ended at its small-case scope, with 36 native accounts
and five model calls unused; this was not an AI claim that all options were
exhausted. Previous studies were preserved.

The full 408-proposal search, 512-account allowance, 24-call allowance and
financial validation thresholds remain unchanged. No full scanner was run for
this release. GitHub's release workflow additionally builds the exact archive
and checks Windows/Linux runtime partitions and fresh installation. Its exact
run and outcome are recorded with the published release rather than attributed
to an earlier version.

## Upgrade and scope

Use the versioned ZIP and its SHA256SUMS. Preserve your private settings and
saved data when upgrading. Optional runtimes retain their own compatibility
requirements. This release does not guarantee that a scanner has a passing
strategy, that historical returns will repeat, or that every broker has been
qualified live.
