# Preview.31 — one complete operating-point decision loop

New editable launches use automatic actions v3 and capital planning v5. Existing
saved v1/v2 actions and v3/v4 capital reports keep their frozen semantics.

The controller diagnoses native request constraints, tests bounded capital/size
remedies, selects one account by funding evidence rather than profit, freezes
it, and automatically validates those exact settings. Each size has its own
fee/slippage and stop-risk capital floor. Zero-fill sizing uses that request's
frozen scheduled opening price; missing evidence remains explicit.

Exploratory remedies reserve thirteen additional accounts: an original-settings
baseline at matched capital, a higher-cost pair, four nearby settings and three
paired expanding-prefix diagnostics. Strict/historical later-window remedies
require the full twenty-one-account programme, including all normal/stressed
later windows and final comparison. They use remaining original allowance and
block if it cannot fund every check. The unchanged paired-block assessment,
sample/design gates, risk limits, 408 proposals and 512-attempt ceiling remain.

Passing historical checks creates an explicitly derived candidate whose native
report, selected capital, settings and saved replay all agree. The primary
search, trials and objective winner remain recorded. Failure keeps the original
financial result. Identical primary settings reuse their existing checks.
Reopening verifies reports and receipts with zero new calculations. Reused
history never establishes independence or a trading recommendation.

## Qualification

Verification uses small deterministic cases, a tiny native callback bridge,
native affordability/risk examples and the existing saved study's metadata.
No full scanner or new full-budget search was run for this batch. The actual
saved v7 study restores all 68 recorded search trials and ten dimensions with
zero sampling/calculations and unchanged metadata.

The local candidate uses the existing dependency environment for the production
frontend build; its package records that provenance explicitly. Settings and
research records are preserved by installation checks. Public release and broad
Linux host qualification are separate, incomplete work; this candidate does not
claim full production qualification or new financial performance evidence.

The design follows established separation of sizing, portfolio limits and
out-of-sample evaluation described in [QuantConnect position sizing](https://www.quantconnect.com/docs/v2/writing-algorithms/trading-and-orders/position-sizing),
[walk-forward optimization](https://www.quantconnect.com/docs/v2/writing-algorithms/optimization/walk-forward-optimization)
and [Backtrader sizers](https://www.backtrader.com/docu/sizers/sizers/).
