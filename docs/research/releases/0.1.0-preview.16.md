# OpenAlgo Research 0.1.0-preview.16

A performance-only patch on OpenAlgo 2.0.2.7. Search budgets, financial versions,
dependencies and installation steps are unchanged. Feature development stays frozen.

## Changes

- Hash and publish one bounded detached checkpoint snapshot, removing a second
  full copy. Unusual/oversized values retain the existing fallback.
- Reuse a scoped owner-thread connection for fresh cancellation/ownership reads.
  Every callback still checks current database state; no row cache or reduced
  checking frequency. Helper threads and heartbeat writes stay independent.

## Qualification

122 focused checks passed, covering exact saved output, snapshot mutation/bounds,
publication recovery, pause/resume, cancellation races and resource cleanup.
Matched short native VectorBT/Optuna continuations preserved exact scientific
checkpoints: three late proposals took median **3.935 →3.005s** (23.6% less), and
whole short continuation including recovery **10.412 →8.647s** (16.9% less).
These warmed isolated-write comparisons are not a new whole-run timing promise.
The last complete cached real-sample optimisation remains **6m50.091s**, measured
on preview.15; its full import/save/reopen journey included operator time.
See [verification](../VERIFICATION.md#trial-bookkeeping-correction--22-october-2026).

No broker calls or live orders were used for this patch. No platform/setup or
frontend contracts changed, so the full installation matrix was not repeated.
Previously validated frontend assets are reused after source and asset checks.

## Install and update

Download the complete
[preview.16 ZIP](https://github.com/mamamiya7/openalgo-research/releases/download/research-v0.1.0-preview.16/openalgo-research-0.1.0-preview.16.zip)
and verify it against `SHA256SUMS`. Extract all files and run **Setup.cmd** on
Windows or **setup-research.sh** on Linux. Do not download Setup.cmd alone.

Existing users: stop the app and worker, back up the application and data,
preserve existing data paths, update files and restart. See
[update instructions](../RUNTIME.md#preserve-data-during-updates). No new migrations.
