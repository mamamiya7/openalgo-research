# OpenAlgo Research 0.1.0-preview.10

Maintenance release on the same reviewed OpenAlgo 2.0.2.7 and locked calculation
libraries as preview.9. Feature development remains frozen.

## Runtime correction

Portfolio progress no longer scans the complete research storage directory every
quarter second. It samples quota once per ten seconds per job, while retaining
the existing cancellation/worker checks and strict quota admission for every new
artifact and checkpoint. No price, execution, search or financial-result logic
changed. Preview.9's worker, recovery and saved-analysis fixes are included.

## Qualification

- Chrome checks on the operator's normal installation used a real CSV with
  1,850 dated signals and 144 NSE stocks. Fresh Fyers daily acquisition admitted
  29 missing candles alongside 2,932 existing candles. An identical fresh run
  reused all 2,961 candles without broker requests and reproduced the result.
- A bounded minute test used four actual dated observations with explicit
  next-session intraday execution. All 64 required minute candles were newly
  admitted from Fyers, then reused without broker requests and with an identical
  result. This is not reconstructed intraday scanner history.
- Warm full-CSV daily runtime fell from 37.387 to 13.885 seconds after the fix.
  First use after app restart took 44.552 seconds, including engine initialization.
  Minute acquisition/backtest took 8.217 seconds; its cache repeat took 1.153 seconds.
  These are observed fixed-backtest timings, not a full automatic-search benchmark
  or performance promise for other machines, brokers or data scopes.
- All saved executable OHLC matched native Historify readback, receipt hashes
  verified, and the 63 prior saved runs and configuration were preserved. No live
  orders, trading-mode changes or cache purges were made.
- The affected worker/publication suite passed 36 checks, with two Windows
  symlink-privilege skips. Four new cases check quota sampling, cancellation,
  worker replacement and immediate artifact quota rejection. Lint passed.
- Package, distribution and installer-safety contracts passed **71 checks**, with
  one Windows symlink-privilege skip. The complete Windows/Linux and numerical matrix is not
  repeated: dependency locks, host calls, launchers and frontend inputs are
  unchanged. Frontend assets are reused only after exact input/hash validation
  against the immutable preview.9 package.

See the [broker acceptance record](../VERIFICATION.md#broker-history-and-cache-acceptance--22-october-2026)
and [preview.9 notes](0.1.0-preview.9.md) for their separate scopes and limits.
Private source files, broker credentials, prices and saved results are excluded
from the public package. Other brokers and full intraday histories remain outside
this acceptance run.

## Install and update

Download the complete
[preview.10 ZIP](https://github.com/mamamiya7/openalgo-research/releases/download/research-v0.1.0-preview.10/openalgo-research-0.1.0-preview.10.zip)
and verify its checksum using the accompanying `SHA256SUMS` file. Extract all
files, then run **Setup.cmd** on Windows or **setup-research.sh** on Linux.
Do not download Setup.cmd alone. VectorBT and Optuna are included in setup;
Nautilus remains optional. Installation steps have not changed.

For an existing installation, stop its app and research worker, retain a complete
backup of application source, configuration, databases, Historify and research
artifacts, then follow the [update instructions](../RUNTIME.md#preserve-data-during-updates).
Keep the existing data paths. The fix requires updated application files and a
worker restart; restarting preview.9 alone does not install it. There are no new
dependency locks, platform requirements or database migrations.
