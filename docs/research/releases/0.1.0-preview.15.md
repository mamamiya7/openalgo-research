# OpenAlgo Research 0.1.0-preview.15

A frozen-feature performance correction on OpenAlgo 2.0.2.7. Dependency locks,
financial versions, search budgets and installation steps are unchanged.

## Changes

- Reuse successful stock/market input validation within one bounded job scope
  only after checking the complete current content. Changed or unusual inputs
  still pass full validation; no approval survives the job.
- Verify saved fit selections and sizing controls without republishing unchanged
  evidence on recovery. New evidence and pre-engine reservations still publish.
- Check live ownership during normal replay without taking the database writer.
  Pause acknowledgement still reserves the writer and rechecks all fences.

## Qualification

158 focused checks passed, including exact saved results/checkpoints, native
pause/resume, cancellation races, changed-input rejection and resource cleanup.
Matched short native-worker continuations used actual saved CSV evidence,
isolated writes and read-only ordinary-store quota checks. Early continuation
was 7.783 →6.661s; late continuation was 13.785 →10.141s (26.4% shorter), mostly
setup/recovery. Late new-proposal work alone was 3.982 →3.851s. Scientific
checkpoint hashes matched exactly. These are short warmed comparisons, not a
new complete-run timing promise. Growing checkpoint work remains a limitation.
See [verification](../VERIFICATION.md#validation-and-replay-correction--22-october-2026).

No broker calls or live orders were used. No platform/setup contracts changed,
so the full installation matrix was not repeated. Frontend assets are reused
only after matching their source and asset hashes.

## Install and update

Download the complete
[preview.15 ZIP](https://github.com/mamamiya7/openalgo-research/releases/download/research-v0.1.0-preview.15/openalgo-research-0.1.0-preview.15.zip)
and verify it against `SHA256SUMS`. Extract all files and run **Setup.cmd** on
Windows or **setup-research.sh** on Linux. Do not download Setup.cmd alone.

Existing users: stop the app and worker, back up the application and data,
preserve existing data paths, update files and restart. See
[update instructions](../RUNTIME.md#preserve-data-during-updates). No new migrations.
