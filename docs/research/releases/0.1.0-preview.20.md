# OpenAlgo Research 0.1.0-preview.20

This patch reduces repeated runtime bookkeeping in automatic research. Features,
financial semantics, the 408-proposal/512-account programme, dependency pins and
validation contracts remain unchanged. OpenAlgo stays at 2.0.2.9, charts 2.6.7.

## Changes

- Reuse the original opportunity receipt only within the two resident frozen
  period windows. Reports receive detached copies; evaluated-account evidence
  is still rebuilt for every settings, gate and cost-stress calculation.
- Use bounded plain-JSON encoding for eligible provenance byte checks and
  evaluation fingerprints. Exact representations and hashes are preserved;
  unusual or oversized inputs retain their existing streaming fallback.
- Admit immutable string keys without a redundant recursive copy. Node, byte
  and depth limits, cycle rejection and detached ownership remain enforced.
- Check regular artifacts first in strict quota scans. Every entry is still
  counted, symlinks rejected and every directory iterator context-managed.

## Qualification

143 focused tests passed, plus two opportunity-cache isolation/eviction tests.
This covers byte limits, canonical identity, provenance, current account evidence,
checkpoint integration, quota bounds and scan cleanup. No persistent resource,
worker, database connection or descriptor was added. The opportunity cache is
run-scoped and bounded by the existing two-window residence limit.

Four matched native continuations from the same eight-trial checkpoint all
produced the exact same scientific checkpoint hash, ten trials and eleven
accounts. After a warm-up case, new two-proposal intervals were 7.335s (patched),
8.459s (baseline), 9.146s (patched); complete continuations were 15.425s, 15.753s,
16.598s. This spread does not support a reliable whole-run speedup percentage.
A separate bounded-provenance encoding microbenchmark fell from 0.394-0.418s
to 0.262-0.289s; it measures only that guard, not full research.

## CSV journey completed in Chrome

A date-coverage-admitted subset of 83 original private signals / six stocks
completed historical optimisation: 272 evaluated proposals, 296 accounts and
294 development histories independently re-read and verified. All four primary
fits evaluated their full 68 trials. The configured maximum remains 408 proposals
and 512 accounts: the existing conditional extra-seed searches were inapplicable
after unsupported checks; no budget was reduced or validation bypassed.

The installed app resumed its eight-trial checkpoint after the patch. Execution
from recorded search start to completion was 15m21.218s; resume click through
completion was 15m32.967s. The earlier pre-patch preparation/eight-trial segment
was 2m37.090s. Combined active wall segments were therefore about 18m10s,
excluding the paused investigation, tests and restart. The UI timer includes
that pause and is not an active-runtime measurement. This is a warm-price,
new-process run, not a clean full-run before/after benchmark.

All 362 required daily execution candles were cached, with zero downloaded.
The exact selection report took 4.408s, then a named tested setup was saved.
Chrome reload retained the setup, decision note and evidence; opening its saved
report reproduced 46 closed trades, 3.15% selection return and 4.31% maximum
drawdown (rounded UI values). The final historical comparison
retains the original settings and does not support an independently validated
improvement. No private input, report or screenshot is included in this release.

No trading action or mode change is part of qualification.

A fresh preview.19 download/setup attempt on the maintainer's Windows host
installed the locked dependencies but Windows Application Control blocked the
new Python launcher. The existing approved installation runs; this does not
establish fresh-install success under that policy, and no policy was bypassed.
