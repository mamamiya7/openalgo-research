# OpenAlgo Research 0.1.0-preview.24

Chartink imports now start price and research-input preparation when their saved
setup opens in native OpenAlgo. The page shows actual preparation progress and
offers Stop and Retry. Reviewing settings can overlap broker downloads; opening
the page does not start a backtest or optimization.

Preparation uses the existing bounded queue, acquisition batches, native broker
lease, cancellation and storage limits. Run waits for matching preparation even
when download batches yield. Launching changed settings cancels obsolete work.
Preparation creates neither a tested setup version nor financial history.

Fixed daily backtests can reuse completed prepared inputs after exact source and
specification binding, fresh native execution/auxiliary calendars and archive
checks, acquisition receipt and coverage verification, and retained feature
validation. Other modes use the warmed price cache through normal preparation;
their page status describes this distinction. Changed or unverified inputs fall
back to ordinary preparation. Existing exact saved replays remain unchanged.

Search budgets, engines, trading rules and validation are unchanged. Starting
earlier reduces the wait after Run; it does not eliminate broker work or promise
every scanner will finish within one minute.

## Qualification

177 frontend journey tests and 90 server library, worker and preparation
tests passed. The dedicated early-preparation suite covers actual worker
publication, a real small VectorBT handoff, batch-yield dependency ordering,
ownership, CSRF, queue capacity, cancellation, settings changes and stale-source
fallback. Production frontend build, type checking and focused style checks pass.

The resource audit checked short-lived database sessions, existing joined worker
leases, artifact readers and browser polling cleanup. Repeated status/start calls
kept the preparation pointer/job count flat and closed every observed database
connection. No new thread pool or persistent in-memory cache was introduced.

## Installed acceptance

The existing 146-stock, 1,869-signal Chartink setup automatically prepared its
inputs on landing, before Run. This cached-data preparation took **37.067s**.
The subsequent fixed backtest reused the identical prepared-input artifact and
completed in **36.483s** from job creation (**37.581s** from the click), including
full run validation and saved results. Preparation and Run are separate measured
intervals; their combined work is about 73.55s, before user review time.

All financial evidence matched the previous cached baseline exactly: account
engine records, ledger, equity curve, execution, rules, summary and analysis.
The tested setup was saved, reloaded and its exact report reopened. The existing
coverage gap and scanner repainting qualification remain. This acceptance used
cached broker prices; it does not claim a new-download timing guarantee. Private
scanner data, figures and screenshots are excluded from the public distribution.
