# OpenAlgo Research 0.1.0-preview.12

Preparation performance patch on the same OpenAlgo 2.0.2.7, dependency locks and
financial versions as preview.11. Installation steps are unchanged.

## Changes

- Missing daily stock warm-up history can overlap two windows through the native
  OpenAlgo history service. Its shared rate limiter remains in force. At most two
  responses are retained; writes, exact readback, provenance, receipts and
  checkpoints are processed in the original order on the caller thread.
- Each preparation job owns one lazy two-thread executor and joins it on success,
  cancellation or failure. Request budgets, cancellation and adapter timeouts stay
  active. Already returned bounded responses finish across the local soft segment
  deadline. A sibling may already have been queried when the first request fails;
  its data is not admitted after that failure. Standalone/single-window acquisition
  remains serial. No broker or Historify core was changed.
- Correlation preparation reuses one day's arrays, variability flags and source
  identities. Ordered numerical pair calculations, lookbacks, volume provenance
  and allocation rules remain unchanged; the entire saved receipt is identical.

## Qualification

- The original real-CSV run checked all 9,028 executable candles from cache in
  about 20 seconds. Most of its roughly twelve-minute wait was auxiliary stock
  warm-up and index context acquisition, rather than an execution-data redownload.
- A read-only repeat covered all 144 actual stocks and 37,584 cached warm-up
  candles in **40.733 seconds**, with every OHLC equal to saved evidence. Broker
  calls, native archive writes and provenance capture were prohibited. This covers
  stock preparation/checkpointing, not all preparation stages or the whole search.
- Actual derived portfolio preparation fell from **65.515 to 48.151 seconds**,
  with the same complete receipt and identity. ATR preparation was unchanged.
- A controlled two-response network wait fell from **0.241 to 0.122 seconds**,
  with identical responses. This verifies overlap, not live-broker throughput.
  Fresh broker wall time has not been retimed; valid cache was not deleted.
- 113 focused acquisition, exact-correlation, ordered-error, request-budget,
  cache-reuse, limiter and resource checks passed. The numerical assumptions and
  supported profiles are unchanged. The full Windows/Linux matrix was not repeated.
- Frontend assets are reused from preview.11 only after matching every frontend
  input and asset hash. No dependency, host-call or setup contract changed.

## Install and update

Download the complete
[preview.12 ZIP](https://github.com/mamamiya7/openalgo-research/releases/download/research-v0.1.0-preview.12/openalgo-research-0.1.0-preview.12.zip)
and verify it against `SHA256SUMS`. Extract all files and run **Setup.cmd** on
Windows or **setup-research.sh** on Linux. VectorBT and Optuna are included;
Nautilus remains optional. Do not download Setup.cmd alone.

Existing users must stop the app and worker, back up their source/configuration
and data, preserve the existing data paths, update the application files, then
restart. See [update instructions](../RUNTIME.md#preserve-data-during-updates).
There are no new migrations. Preview.11's progress, historical-mode and runtime
improvements are included.
