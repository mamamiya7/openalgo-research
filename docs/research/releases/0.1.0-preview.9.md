# OpenAlgo Research 0.1.0-preview.9

One-click journey patch on the same reviewed OpenAlgo 2.0.2.7 and locked
calculation libraries as preview.8. The complete browser-driven import, research,
analysis, save and reuse journey passed with controlled native Historify data.

## Essential one-click fixes

The complete browser journey exposed four integration gaps:

- Current automatic runs now receive their durable job identity from the worker,
  including when compatible saved progress is resumed.
- Successfully admitted native daily prices are marked frozen. Older verified
  calculation checkpoints receive that lifecycle marker in memory, preserving
  their original saved input artifact and mandate.
- Study activity accepts the registered v16 portfolio-allocation choices, so
  recording a valid allocation proposal does not interrupt its calculation.
- Optional analysis receives the frozen execution descriptor and uses the same
  recorded parameter limits as its reader. Charts no longer reject valid current
  studies at the process boundary. No search or prices are recomputed.
- Trial settings name recorded exits, sizing, trading times and trailing stops
  instead of showing blanks or numbered placeholders.

Automatic findings also show market-condition performance, sample sizes and
insufficient-data states from frozen prices. Development and final-period results
stay separate. This is reporting only: no extra downloads or account simulations,
no new selection rules, and no changed mathematical policies or search budgets.
Existing saved studies keep their recorded calculation versions.

## Install and update

Download the complete
[preview.9 ZIP](https://github.com/mamamiya7/openalgo-research/releases/download/research-v0.1.0-preview.9/openalgo-research-0.1.0-preview.9.zip),
verify its supplied SHA-256, extract all files and run Setup.cmd on Windows or
setup-research.sh on Linux. Do not download Setup.cmd alone. VectorBT and Optuna
are installed together; Nautilus remains optional.

Preview.8 lacks these automatic-worker fixes, so the patch requires updating the
application files, not only restarting an old installation. Stop the app and
worker first and retain a complete source, configuration, database, Historify and
research-artifact backup. Keep the same data paths. There are no dependency-lock,
platform-version or migration changes in this patch. See the
[runtime guide](../RUNTIME.md) and [distribution guide](../DISTRIBUTION.md).
