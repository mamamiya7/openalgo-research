# Preview.32 — bounded research supervision in the existing AI Agent

The built-in chat Agent now reads research decisions, exact capital/settings,
failed checks, missing evidence and remaining attempts. One confirmed historical
plan permits at most three registered experiments: funding/size, holding-period
cost or temporal remedies, and causal diversification. The native worker runs
the declared queue, validates each changed account and saves/reopens the first
accepted result. Failure retains the original result with explicit reasons.

Authority belongs to the signed-in owner and conversation. Persistent proposal
identities prevent duplicate work. New Agent turns cannot reset the original
512-account or 64-interrupted-account ceilings. All required validation is
reserved before admission; no original proposals or checks are removed. Missing
prices/evidence and fixed position/liquidity constraints do not justify blindly
adding funds. Numerical accounts remain native VectorBT calculations.

Exploratory supervisor candidates must also pass all three declared historical
prefixes. Exposed later/final results cannot select another performance remedy.
Only a funding remedy is permitted for those studies, without independent status.
Changed-point identities use the exact native capital representation. Checkpoint
resume rechecks settings, calendar, gate, design and financial evidence.

This is finite research automation, not continuous background LLM reasoning.
The Agent chooses the initial queue; the worker continues it after chat returns.
New verified development failures can inform another Agent turn within the same
remaining allowance. `awaiting_plan` explicitly requires that turn. No provider
is activated by installation alone. The user subsequently connected ChatGPT;
the [actual six-case qualification](../CHATGPT_LIVE_QUALIFICATION_20261024.md)
does not qualify autonomous decision quality. It found read-without-action,
infeasible finite sizing and advertised but unavailable holding-grid remedies.
No accepted result was produced by the live model batch.

Verification uses small saved-data cases only. The native fixture starts with
an unfundable INR1 account, tests INR5000 with smaller trade size and correctly
rejects it on validation. Completed checkpoint resume adds zero calculations.
Separate canonical save/reopen tests check exact accepted report identity and
idempotent retries. There is no new full scanner or 408-proposal run.

Storage backup/restore preserves supervisor authority and budget history. No
trading tool, broker setting, credential, search objective or hard risk limit is
changed. Public release and Linux/eventlet/gthread host qualification remain
pending; the existing published download remains unchanged.
