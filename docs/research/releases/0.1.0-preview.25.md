# OpenAlgo Research 0.1.0-preview.25

This preparation performance batch keeps the existing research features,
financial rules, engines, saved-evidence contracts, search budgets and validation.

## Changes

- Canonicalize historical bars and parse their availability once per preparation,
  sharing exact prior-window bytes across overlapping causal return windows.
- Reuse the independently normalized forward and reverse NumPy correlation
  values from each pair calculation. Saved receipt equality remains exact.
- Check detached volume observation seals once per preparation; every entry
  retains its own OHLC alignment, provider, calendar, availability and complete
  twenty-session window checks. Reconstruction of saved features still runs.
- Keep large stock contexts on the bounded validation-reuse path by encoding
  individual records within the existing node limits and an aggregate 32 MiB
  signature ceiling. Changed content still triggers full semantic admission.
- Share context size/hash serialization, validated session closes and receipt
  bytes. Avoid copying discarded full histories for period projections and
  calculating unused recovery bindings for already admitted contexts.
- Retain up to 4,096 causal feature entries under a 32 MiB heap limit in the
  existing private owner, avoiding the former 512-entry LRU thrash on large
  scanners. Owner, provider, copy-on-return, eviction and cleanup checks remain.
- Allow fully prepared daily v16 automatic inputs through the existing exact
  source/specification/calendar/archive guarded handoff. The normal run still
  reconstructs its features, checks its complete recipe and reserves evaluation
  dates before search. Minute and other unsupported handoffs keep normal cache
  preparation.
- Publish fully cached stock records in private groups of at most sixteen and
  four MiB of combined canonical bytes and retained heap. Each group keeps fresh
  storage admission, final quota and entry reconciliation, atomic writes and
  durable checkpoint references. Broker boundaries still persist individually;
  writer scopes close before progress, checkpoint or network work.
- Encode large native portfolio receipts as bounded canonical pieces for size,
  hashing and seal checks. This keeps the 49 MB, 146-stock receipt on the C
  encoder path instead of repeatedly streaming individual JSON tokens in Python.
  Combined bytes, each piece, recursion and fragment counts stay bounded;
  unsupported content keeps the original streaming validation and error order.

## Qualification

364 focused regressions pass, with two Windows platform skips. They include exact legacy return, ordered
correlation and complete feature receipts; malformed and mutated evidence;
146-stock context reuse with a changed final stock; 1,869-clock bounded cache
reuse; daily automatic recipe/budget integrity; worker handoff, queue, cancellation
and freshness guards. Focused style checks pass. No new files, connections,
executors or persistent module caches are owned by the calculation changes.
All new retained data is bounded by its preparation or existing private owner.

The installed Windows acceptance used 1,869 signals across 146 stocks, the
original trading rules and existing cached prices. Opening the derived setup
through the durably saved fixed-backtest result took **58.859 seconds**;
preparation creation through saved result took **54.367 seconds**. Preparation
took 28.122 seconds, overlapping the main job's queue wait. The main job,
including that queue, took 48.420 seconds; these overlapping durations must not
be added. Every financial result field, ledger, equity curve and engine record
matched preview.24 exactly. The tested setup was saved, reloaded and its stored
report reopened successfully.

This timing qualifies the cached-price fixed-backtest journey. The same
146-stock scan's automatic v16 attempt correctly stopped at its unchanged
history check: 160 recorded sessions cannot supply the four separate windows
of at least 88 sessions required by its existing holding-period rules. No shorter
holding period or historical-only validation mode was substituted. The full
automatic budget remains 408 proposals / 512 accounts; this scanner therefore
does not provide a completed full-budget automatic timing claim. Fresh network
downloads and different research inputs have not been promised under one minute.
